# Routing profile editor saves overwrite changes made elsewhere

- found: 2026-11-19, plan: 20261119-provider-toggle-panel-ui, phase: evaluation
- severity: major
- area: apps/web/src/features/personal-quota-support/services/api/routingProfiles.ts

The profile editor (Default and key profiles) saves the whole profile it loaded with a `PATCH /config` (`saveKeyProfile`, `routingProfiles.ts:892`; `saveSharedProfile`, `routingProfiles.ts:1036`). That PATCH is not conditional on the config the editor opened with. The body is the full profile (`profileBody`, `routingProfiles.ts:535`), so a save of an unrelated field overwrites any change made after the editor opened: in another tab, by another admin, or by a direct edit of the config file. The read-back (`routingProfiles.ts:910`, `:1060`) then confirms the stale value. This has been deliberate so far: the Codex speed plan made only the speed table conditional and recorded "the editors stay unconditional" (`docs/plans/completed/20261118-codex-speed-panel-ui.md:164`).

The race reverts mode, API key, preferred account, fallback and speed. For example, a stale save puts back a paid Claude API key that another admin replaced. It also recreates a key profile that another admin reset, or creates one for a key whose editor opened while the key still followed the Default profile, from the copy the editor started with.

The provider `disabled` flag mostly fails closed. A save sends `disabled` only for a provider that is off, or one the editor switched back on from off (`sentDisabled`, `routingProfiles.ts:483`). A provider that stays on is left out of the PATCH, so CPA keeps the flag stored in an existing profile. A profile the PATCH creates starts with the provider on. So before a key save that leaves a flag out, `saveKeyProfile` reads the stored config (`configSnapshot`, the file the PATCH merges into, not the profiles CPA has loaded). When the key owns no profile there, it sends each left-out flag as that file's Default holds it, and the PATCH is conditional on that read's version. A change landing between the read and the PATCH therefore fails with `ConfigChangedError`. Two gaps remain. Behind a proxy that drops or weakens the `ETag`, that PATCH goes out unconditionally, and such a change can still leave a provider on. And an editor that opened with a provider off writes `disabled: true` again, even if another admin switched the provider on in the meantime. Under `supported: false` the shared save sends no `disabled`, so the locked Default editor does neither.

Fix direction: make editor saves conditional on the config the editor opened with, as the speed table's key writes are (`useKeyProfiles.ts:352`, `:394`). When the modal loads the profiles, read `configSnapshot()` first. Send that version as `If-Match` from `saveKeyProfile` / `saveSharedProfile` in place of the version the key save reads just before it writes. On `ConfigChangedError`, keep the draft open, say that the profile changed, and offer a reload. Two questions remain. On a backend without a strong ETag, should the panel save unconditionally as today or refuse like `config_version_missing`? And does the gap between the loaded config and the file need the empty conditional PATCH that `saveKeyDefaultCopy` uses?
